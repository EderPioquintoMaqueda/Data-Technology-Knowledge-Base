# ✉️ Writing Professional Emails and Messages

## 1. Email structure
| Part | Formal | Neutral / friendly |
|---|---|---|
| Greeting | *Dear Ms. García,* | *Hi Ana,* / *Hello team,* |
| Opening | *I am writing to…* | *I hope you're doing well.* / *Quick question about…* |
| Purpose | *I would like to request…* | *Could you…?* |
| Details | *Please find attached…* | *I've attached…* |
| Action | *I would appreciate it if you could… by Friday.* | *Can you take a look by Friday?* |
| Closing | *I look forward to hearing from you.* | *Let me know if you have any questions.* |
| Sign-off | *Kind regards, / Best regards,* | *Best, / Thanks, / Cheers,* |

## 2. Templates
### Request
> **Subject:** Access request – production read replica
> Hi Luis,
> Could you please grant me read-only access to the production replica? I need it to validate the monthly revenue numbers before Friday's report.
> Thanks in advance,
> Eder

### Status update
> **Subject:** [Update] Sales pipeline migration – week 46
> Hi team,
> Here's this week's update:
> ✅ **Done:** staging tables migrated to PostgreSQL 17.
> 🔄 **In progress:** dbt models for orders (80%).
> ⚠️ **Risk:** the vendor API changed its format; I'm working on a fix.
> 📅 **Next:** full test run on Tuesday.
> Best, Eder

### Reporting a problem
> **Subject:** Issue: nightly ETL failed (Nov 18)
> Hi all,
> The nightly ETL **failed at 02:14** due to a timeout on the orders API. **Impact:** today's dashboard shows data up to Nov 17. **Next steps:** I've re-run the job manually and it's running now; I'll confirm once it finishes (ETA 10:30). I'll also add retries to prevent this in the future.
> Sorry for the inconvenience,
> Eder

### Following up
> *Hi Ana, just following up on my previous email about the data dictionary. Do you have any update? Happy to jump on a quick call if that's easier.*

### Saying no politely
> *Thanks for thinking of me. Unfortunately, I don't have the bandwidth to take this on this sprint, but I could look at it next week. Would that work?*

## 3. Softening language (sound polite, not rude)
| Too direct | Softer |
|---|---|
| Send me the file. | Could you send me the file, please? |
| You're wrong. | I think there might be a misunderstanding. |
| This is bad. | This could be improved. |
| I need it now. | Would it be possible to have it today? |
| Why didn't you do it? | I noticed it's still pending — is there anything blocking you? |
| No. | I'm afraid that won't be possible because… |

## 4. Chat (Slack / Teams) style
- Short and clear; one message, not five.
- *Hey Ana! Quick question: is the `orders` table refreshed daily or hourly? 🙏*
- *Thread:* reply in threads to keep channels clean.
- Abbreviations OK internally: *FYI, ETA, EOD, PTAL (please take a look), LGTM (looks good to me), WFH, IMO.*

## 5. Reading strategy for technical documentation
1. **Skim** headings and code first (what is this for?).
2. **Scan** for the thing you need (Ctrl+F).
3. Read examples **before** the theory.
4. Note 3 new words per page in [[Vocabulary Database]].
5. Summarise the page in 2 English sentences.
